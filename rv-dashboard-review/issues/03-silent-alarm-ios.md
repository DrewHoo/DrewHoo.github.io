**Severity: high — the audible wind alarm (the safety feature) is most likely silent on iPhone.**

`RVAlerts.soundAlarm()` creates a brand-new `AudioContext` at the moment the alarm fires:

```js
const ctx = new (window.AudioContext || window.webkitAudioContext)();
```

Browser autoplay policy — strictest on iOS Safari, but Chrome too — only allows an `AudioContext` to start **during a user gesture**. Both alarm paths fire outside one:

- The current-conditions alarm fires from the 5-minute `setInterval` weather refresh — no gesture anywhere in sight.
- The route alarm fires inside the form-submit handler, but only after several `await`s (geocode → route → 6 forecast fetches); by then the "transient user activation" window (~a few seconds) has expired.

In both cases the context is created in the `suspended` state, the oscillator "plays" into a suspended context, no error is thrown, and **no sound comes out**. On top of that, `navigator.vibrate` is not implemented on iOS Safari at all — so on an iPhone the alert is reduced to the visual banner, which defeats the point of an audible alarm while driving.

### Fix: unlock one shared AudioContext on the first user interaction, reuse it

```js
// alerts.js
let audioCtx = null;

function unlockAudio() {
  if (!audioCtx) audioCtx = new (window.AudioContext || window.webkitAudioContext)();
  if (audioCtx.state === "suspended") audioCtx.resume();
}

function soundAlarm() {
  if (!audioCtx || audioCtx.state !== "running") return; // never unlocked
  const beepAt = (startTime) => { /* same oscillator code, but using audioCtx */ };
  const now = audioCtx.currentTime;
  beepAt(now); beepAt(now + 0.35); beepAt(now + 0.7);
  if (navigator.vibrate) navigator.vibrate([200, 100, 200, 100, 200]);
}
```

Then in `app.js`, call `RVAlerts.unlockAudio()` from real gestures — the "Warn me about high wind" toggle, the threshold inputs, and the "Plan Route" button (synchronously, before the `await`s):

```js
[alertsEnabledInput, windThresholdInput, gustThresholdInput].forEach((el) =>
  el.addEventListener("change", () => { RVAlerts.unlockAudio(); saveThresholdsFromForm(); })
);
```

### Strongly recommended alongside: a "Test alarm" button

A small button in the Wind Alerts card that calls `unlockAudio()` then `soundAlarm()` does two jobs at once: it *guarantees* the audio is unlocked by a real tap, and it lets the driver confirm the alarm actually works (and hear what it sounds like) **before** trusting it on the road. For a safety feature, "test it in the driveway" is worth a button.
