**Enhancement — add official National Weather Service warnings along the route (free, no API key, fits the existing architecture).**

The wind-threshold system is great for personal limits, but Open-Meteo only supplies *numbers* — it doesn't know about official warnings. The National Weather Service publishes every active alert through a free, keyless, CORS-enabled API that a browser can call directly, same as Open-Meteo:

```
https://api.weather.gov/alerts/active?point={lat},{lon}
```

For an RV, the alerts that matter go beyond wind speed thresholds: **High Wind Warnings** (often issued specifically for high-profile vehicles), severe thunderstorm and tornado warnings, dust storms, flash floods, and winter storm warnings over mountain passes. These carry expert judgment (timing, confidence, "travel not advised for high-profile vehicles" wording) that raw gust numbers can't.

### How it would fit

A small `js/nwsAlerts.js` module in the same style as the others:

```js
const RVNws = (() => {
  async function activeAlerts(lat, lon) {
    const res = await fetch(
      `https://api.weather.gov/alerts/active?point=${lat.toFixed(3)},${lon.toFixed(3)}`,
      { headers: { Accept: "application/geo+json" } }
    );
    if (!res.ok) return [];       // degrade silently — thresholds still work
    const data = await res.json();
    return data.features.map((f) => ({
      event: f.properties.event,        // e.g. "High Wind Warning"
      headline: f.properties.headline,
      severity: f.properties.severity,  // Minor/Moderate/Severe/Extreme
      ends: f.properties.ends,
    }));
  }
  return { activeAlerts };
})();
```

Surface it in two places:

1. **Live card** — check the current position alongside the 5-minute weather refresh; show the event name in the existing red banner (`⚠️ High Wind Warning until 8 PM`).
2. **Route strip** — after planning, query each sampled stop and badge stops that sit inside an active alert area (the route stops are already a perfect set of query points; 6 extra requests, only when planning).

Notes: it's US-only (fine for the audience — degrade to nothing elsewhere); alerts are *active-now*, so for tomorrow's route treat them as "heads up, conditions are already in play", with the threshold forecasts remaining the tomorrow-specific signal. NWS asks API users to send an identifying User-Agent; browsers send their own automatically, which is acceptable for a client-side app at this scale.
