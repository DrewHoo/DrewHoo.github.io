### Ready to paste — `CLAUDE.md`

```markdown
# RV Dashboard

A mobile PWA for RV travel: live GPS speed/altitude + current weather,
next-day route weather forecasts, and user-configurable wind alarms.
Hosted on GitHub Pages at https://mikehoover59.github.io/rv-dashboard/

## Hard constraints

- **No build step, no framework, no npm.** Plain HTML/CSS/JS, editable
  directly and hosted as static files. Do not introduce bundlers,
  transpilers, package.json, or frameworks. (Chosen deliberately so the
  app can later be wrapped with Capacitor and stays maintainable by one
  person.)
- **No API keys, no accounts, no server.** All data comes from free,
  keyless, browser-callable APIs: Open-Meteo (weather + geocoding) and
  OSRM-compatible routing. Any new data source must follow the same rule.
- **US units in the UI**: mph, feet, °F.

## Architecture

- `index.html` — all page structure; scripts loaded in dependency order.
- `js/*.js` — one concern per file, each an IIFE exposing a single
  global namespace (`RVGeo`, `RVWeather`, `RVRouting`, `RVAlerts`);
  `js/app.js` is the only file that touches the DOM and wires the
  others together. Follow this pattern for new modules.
- `css/style.css` — dark theme, large glanceable numbers. Design for a
  phone on a dashboard mount: big text, high contrast, minimal taps.
- `service-worker.js` — caches the app shell for offline open; API
  calls always go to the network.
- Settings persist in `localStorage` (see `RVAlerts` for the pattern).

## Gotchas (read before changing anything)

- **Adding/renaming any shell file** (HTML/CSS/JS/icon) requires adding
  it to `SHELL_FILES` in `service-worker.js` AND bumping `CACHE_NAME`,
  or installed phones won't fetch it offline.
- Weather is polled every 5 minutes, not per GPS tick — keep API usage
  polite; these are free community services.
- Geolocation only works over HTTPS (or localhost). Real GPS behavior
  can only be tested on a phone against the live GitHub Pages site.
- `soundAlarm()` depends on an AudioContext unlocked by a user gesture;
  don't move alarm triggering further from user interactions.

## Workflow

- Test locally: `python3 -m http.server 8420` → http://localhost:8420
  (route planner and weather work; GPS values won't be meaningful).
- Deploy: push to `main`; GitHub Pages republishes in ~1–2 minutes.
- Verify on a phone via the live URL after deploying.
- Keep commits small and messages plain-language.
```

(Adjust the gotchas as the service-worker and alarm issues get fixed.)
