**Severity: high — a pushed fix may never reach phones that installed the app.**

`service-worker.js` serves the app shell **cache-first**:

```js
event.respondWith(
  caches.match(event.request).then((cached) => cached || fetch(event.request))
);
```

Once a phone has cached the shell, it will use those files forever. The only thing that dislodges them is the browser noticing that `service-worker.js` itself changed byte-for-byte (which installs the new cache under the new `CACHE_NAME` and deletes the old one). That means:

- Pushing a fix to `main` **without** editing `service-worker.js` → installed phones keep running the old code indefinitely. The README's "republishes automatically within a minute or two" is true for the website, but not for anyone who added it to their home screen.
- Remembering to bump `CACHE_NAME` on every release is exactly the kind of invisible rule that gets forgotten — and when it is, the symptom is the confusing "I pushed it but my phone still shows the old version".

### Recommended fix: network-first for the shell, cache as offline fallback

This keeps the offline-open property (the stated goal of the service worker) while making every online load pick up the latest deploy automatically — no version bumping needed for routine changes:

```js
self.addEventListener("fetch", (event) => {
  const url = new URL(event.request.url);
  if (url.origin !== self.location.origin) return; // API calls skip the cache

  event.respondWith(
    fetch(event.request)
      .then((res) => {
        const copy = res.clone();
        caches.open(CACHE_NAME).then((cache) => cache.put(event.request, copy));
        return res;
      })
      .catch(() => caches.match(event.request))
  );
});
```

Trade-off: loads now wait on the network when online (fine — these are a few small files), and the app still opens instantly from cache with no signal. A fancier `stale-while-revalidate` gives instant loads with updates one visit later, but for a handful of files the version above is simpler and always fresh.

Keep the `install`/`activate` handlers as they are — pre-caching on install and cleaning old caches on activate both still make sense. And `CACHE_NAME` still needs a bump if a file is ever **added** to `SHELL_FILES` (so it gets pre-cached for offline), just no longer on every code change.
