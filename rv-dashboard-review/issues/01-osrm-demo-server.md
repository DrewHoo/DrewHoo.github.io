**Severity: high — the Route Planner's only backend has no availability guarantee.**

`js/routing.js` sends every routing request to `https://router.project-osrm.org`, which is the OSRM project's **demo** instance. Its own usage policy says it exists for demonstrations, is rate-limited, and offers no guarantee it will be up — and it has historically had multi-day outages. When it's down or throttled, the Route Planner (arguably the app's headline feature) fails entirely with "Routing service unavailable".

### Easiest fix — drop-in URL swap

The FOSSGIS e.V. servers run the exact same OSRM API for the OpenStreetMap community and are the routing backend behind openstreetmap.org itself. One-line change:

```js
const OSRM = "https://routing.openstreetmap.de/routed-car/route/v1/driving";
```

Same request format, same response format — nothing else changes. Still a free community service (be a good citizen: the app's one-request-per-plan usage is fine), but far more appropriate for a live app than the demo box.

### Sturdier fix — fallback chain

Try a primary endpoint, fall back to a secondary before giving up:

```js
const OSRM_ENDPOINTS = [
  "https://routing.openstreetmap.de/routed-car/route/v1/driving",
  "https://router.project-osrm.org/route/v1/driving",
];

async function getDrivingRoute(fromLat, fromLon, toLat, toLon) {
  let lastErr;
  for (const base of OSRM_ENDPOINTS) {
    try {
      const res = await fetch(`${base}/${fromLon},${fromLat};${toLon},${toLat}?overview=full&geometries=geojson`);
      if (!res.ok) throw new Error("Routing service unavailable");
      const data = await res.json();
      if (!data.routes?.length) throw new Error("No driving route found between those points");
      const route = data.routes[0];
      return {
        coords: route.geometry.coordinates.map(([lon, lat]) => ({ lat, lon })),
        distanceMeters: route.distance,
        durationSeconds: route.duration,
      };
    } catch (e) { lastErr = e; }
  }
  throw lastErr;
}
```

If you ever outgrow community servers, OpenRouteService and GraphHopper both have free API-key tiers — but that breaks the nice "no API keys" property, so it's a later problem.

### One caveat worth a README line

Every one of these services computes **car** routes. None of them know about RV height/weight limits, propane-restricted tunnels, or roads unsuitable for a large rig. Worth one sentence in the README ("verify the suggested route is RV-safe — this plans weather, not clearances") so nobody treats the sampled route as RV routing advice.
