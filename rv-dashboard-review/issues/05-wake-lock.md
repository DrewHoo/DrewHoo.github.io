**Enhancement — keep the screen on during a drive with the web Wake Lock API. No Capacitor needed.**

The README lists "running on a car mount without the screen timing out" as something that requires wrapping the app in Capacitor later. Good news: the web platform has this today. The **Screen Wake Lock API** (`navigator.wakeLock`) is supported in Safari on iOS 16.4+ and Chrome on Android — which covers the phones this app targets.

There's also a second, quieter reason this matters: **browsers pause JavaScript timers when a tab is backgrounded or the screen locks.** The 5-minute weather refresh — and therefore the wind alarm — only runs while the app is visible. A wake lock keeps the dashboard visible on the mount, which is exactly what keeps the alerts alive during a drive. (True background alerting genuinely does need the native wrap or push notifications; worth keeping that Capacitor note for that reason instead.)

### Sketch

```js
// app.js
let wakeLock = null;

async function keepScreenOn() {
  if (!("wakeLock" in navigator)) return;
  try {
    wakeLock = await navigator.wakeLock.request("screen");
  } catch (e) {
    console.warn("Wake lock refused:", e.message);
  }
}

// The OS releases the lock when the app is hidden — re-acquire on return.
document.addEventListener("visibilitychange", () => {
  if (document.visibilityState === "visible") keepScreenOn();
});
```

Two UX notes:

- Browsers require a user gesture or a visible page to grant it — calling it from a **"Keep screen on" toggle** in the settings card is the reliable pattern (and lets the passenger turn it off at camp so it doesn't eat battery).
- Expect it to be refused on low battery; the `catch` above handles that gracefully.

This is a small amount of code for one of the most-wanted behaviors of a dashboard app.
